# Arise 0.0.47

Fix package state lost between phase workers, including the binutils-libs 2.47
failure where `src_prepare` entered the wrong source directory after unpacking.

- Preserve changes to `S`, shell variables, readonly values, arrays, helper and
  phase functions, explicit unsets, and compression/strip settings between phases.
- Store the final build environment in binary packages and the installed VDB.
  Carry state through pre-install, post-install, and removal hooks, with atomic
  installed-environment updates.
- Use saved hook definitions when earlier phases replace, create, or remove
  functions. Restore current runtime paths when loading installed environments.
- Correct phase entry directories, missing-source handling, phase identifier
  visibility, isolation path translation, and failed-worker diagnostics.
- Strengthen regression assertions so ignored ordinary phase return values
  cannot make broken behavior appear to pass.

The execution ABI advances to 5. Earlier Arise ABI-2/3/4 packages are selected
for rebuilding because lost state could silently affect installed output.
Unmarked Portage packages are retained. This can add rebuilds to an update plan.

Validation includes the full test and internal race suites, live comparisons
with Portage for EAPIs 7, 8, and 9, and the actual binutils-libs 2.47 unpack and
prepare sequence. See the [phase-state audit](../audits/PHASE_STATE_AUDIT_2026-11-04.md)
for findings, regression evidence, and validation limits.

Arise remains experimental and `~amd64`. The full fresh-stage3 update,
interruption/resume, linkage and reboot acceptance run remains deferred.
The final live-system installation remains a separate manual canary.
