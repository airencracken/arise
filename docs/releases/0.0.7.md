# Arise 0.0.7

Arise 0.0.7 is a correctness-focused release. It independently validates the
final state predicted by every executable package plan, records why candidates
were selected or rejected, and proves that the state produced by real
execution matches the prediction. It also improves package build isolation and
the interactive configuration-update experience.

## Independently validated package plans

Arise no longer relies on agreement with Portage's action ordering as its
primary definition of a correct plan. It applies each proposed plan as a pure
state transformation, then validates the resulting package state against
dependency, slot, blocker, USE, repository, and installed-state constraints
through an independent path.

Execution consumes the exact validated plan and verifies the committed state
afterward. Disposable-root integration tests cover multi-package dependency
repair, and retained live-root evidence covers stale slot-operator repairs
from planning through all eleven successful package transactions.

Verbose plans include a bounded decision ledger explaining retained, selected,
rejected, and skipped candidates. The plan-comparison tooling classifies both
Arise and Portage final states instead of requiring action-for-action identity;
machine-readable evidence distinguishes equivalent valid plans, divergent
valid plans, and invalid outcomes.

Independent validation remains fast enough for normal package-manager use.
During release qualification, a correctness-equivalent `@system` comparison
exposed a severe planning regression. Candidate-policy evaluation was confined
to selected actions, final-state dependency matching was indexed by
category/package, and no-change plans stopped validating the identical package
state twice. Regular tests now guard the large-state lookup shape, while
release resolver workloads require at least a 1.2x median lead over `emerge`.

On the final same-snapshot candidate, Arise planned a shallow `@system` update
in 1.96 seconds versus 3.78 seconds for `emerge`, and a deep/newuse `@world`
update in 3.25 seconds versus 17.98 seconds. Both normalized plans were
equivalent.

## Safer stale-binding repair

Complete-graph resolution now distinguishes a stale installed subslot binding
from a package whose selected version actually changes. When the best visible
version is newer, Arise schedules an upgrade rather than incorrectly forcing a
reinstall of the older installed version.

This was exercised on a live Gentoo system with eleven Perl consumers. The
transaction completed successfully, and the post-transaction comparator
reported zero actions from both Arise and Portage with an
`equivalent-valid` classification.

## Build and synchronization correctness

Package phase workers retain Arise's controlled build environment when
dropping privileges. In particular, `HOME`, cache, and local-data paths remain
inside the package build directory rather than pointing at an unwritable
system account home.

Repository synchronization validates repository identity, repairs permissions
from older clones, publishes new clones atomically, and retains concise
package-change reporting. Package transaction progress now uses durable lines,
preventing concurrent stage output from overwriting merge-completion messages.

## Configuration review

`arise dispatch-conf` now clears stale terminal content before each comparison,
uses semantic color for paths and diff output when color is enabled, and
orders pending configuration updates consistently with the interactive
workflow. Recursive discovery, safe three-way premerge, confined archives,
metadata preservation, and interruption handling remain covered by the
command's test suite.

## Documentation

The project README now leads with what Arise does, how it compares with other
Gentoo tools, how to install it from the overlay, how to build it, and where to
find detailed compatibility and engineering documentation.

## Upgrade

After synchronizing the overlay:

```sh
emerge --ask --oneshot sys-apps/arise
```

Existing Arise installations can also synchronize and reinstall the exact
release:

```sh
arise sync
arise -1 --reinstall =sys-apps/arise-0.0.7
```

Arise remains experimental and testing-keyworded for `~amd64`. Keep Portage
installed as the behavioral reference and recovery fallback.
