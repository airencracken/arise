# Arise 0.0.50

Correct misleading missing-candidate warnings during world updates after an
upgrade through Portage. If the installed package is newer than the ebuilds in
Arise's index, retaining it does not mean the world selection is obsolete.

- Check all matching repository candidates before reporting that none is
  installable. An older eligible ebuild no longer produces the missing-candidate
  warning or deselect advice.
- Report package masks, keyword restrictions and `--exclude` separately from
  missing candidates. Preserve saved version, slot, repository and USE
  constraints in warning diagnostics.
- Include `arise index` after the documented Portage bootstrap to refresh
  Arise's metadata after an external repository sync.

The regression reproduces the warning with Arise 0.0.49 installed and an older
indexed ebuild. Additional cases cover policy blocks, constrained selections,
retained dependencies and genuinely missing candidates. Package planning is
unchanged; the execution ABI remains **6**.

When repositories were synchronized through Portage, refresh Arise's index
after the running transaction finishes:

```sh
arise index
```

Arise remains experimental and `~amd64`. The full host update and fresh-stage3
acceptance run remain separate checks.
