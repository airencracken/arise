# Arise 0.0.34

Uncached overlays now participate in dependency resolution. Previously, Arise
could list their ebuilds in search while excluding them from the resolver,
producing a misleading missing-package or short-name parser error.

- `arise index` and the refresh after `arise sync` evaluate uncached ebuilds
  natively through Arise's sandboxed Bash worker. No manual cache-generation
  command or change to the overlay is required.
- Evaluation includes eclasses from repository masters, computed package
  metadata, inherited dependencies and USE flags, and the EAPI 8/9 accumulation
  rules for `PROPERTIES` and `RESTRICT`. Build and installation phases do not run.
- Uncached metadata is reevaluated on refresh, including when only an inherited
  eclass changes. Failed evaluations report their cause and leave the previous
  index active.
- Missing short package names report an absent indexed package rather than an
  atom syntax error. Ambiguous names still require a category; for example,
  `www-apps/imvault` distinguishes the application from its service accounts.

After upgrading, run `arise index` and retry the package command. Metadata
evaluation uses the existing Bash and Gentoo sandbox runtime dependencies and
supports EAPIs 7, 8, and 9.

Regression coverage exercises uncached-overlay indexing and resolution,
inherited-eclass changes, failure atomicity, required metadata, cancellation,
and inheritance failures. The live metadata differential compares Go, live Git,
service-user, and service-group ebuilds against Portage.
