# Arise 0.0.42

Local release candidate for the October stabilization audit. Publication is
pending the remaining clean-image execution gates.

- Fixes the Perl world-update blocker loop and repeated installed-USE evaluation.
  The audited host pretend falls from over four minutes to about five seconds,
  including verbose output. Cached source download totals no longer rehash
  complete archives during display; acquisition still verifies their contents.
- Tightens ABI rebuilds, retained slots, dependency domains, exclusions, newuse,
  and independent transaction validation.
- Preserves resume checkpoints through planning and declined confirmation,
  accepts saved bare CPVs, and retains original world selections across progress
  updates. Pending same-version rebuilds run even with `--resume --update`.
  Resume no longer promotes dependencies into world. Old checkpoints
  remain readable but cannot reconstruct favorites they never stored.
  Reapply original build, binary, root and job options when resuming; complete
  option-context replay remains unfinished.
- Honors `--ask` for an empty update and preserves unrelated resume state.
  Supplied approval also guards empty-update bookkeeping; resume semantics and
  saved world selections are bound into the approval receipt.
- Fixes source and binary upgrades in disposable roots, including replacement
  VDB removal and obsolete payload cleanup. Recovery restores the currently
  installed same-slot predecessor and supports failure, retry, and replay.
- Plans remote binaries from one `Packages` index per host. Pretend and declined
  confirmation acquire no archives. Confirmed execution acquires the selected
  dependency closure with size, digest, and container verification.
- Preserves binary ABI subslots in generated indexes and selects the newest
  compatible build instance. Required binary lifecycle hooks now trigger source
  fallback or an explicit rejection instead of being silently skipped. Full
  binary lifecycle execution remains unfinished.
- Makes failed comparison commands inconclusive and retains their underlying
  launch and execution diagnostics.

Verification and remaining gaps are recorded in the
[stabilization review](../reviews/2026-10-11-stabilization-release.md) and
[world-update audit](../audits/WORLD_UPDATE_AUDIT_2026-10-11.md).

The fresh stage3 resolves and passes recipe/policy preflight, but execution is
blocked by the available namespace's single UID/GID mapping. A complete update,
interruption/resume, linkage, and reboot acceptance pass is still required in an
environment with normal package/build-user ownership. This candidate does not
close the stabilization punchlist or certify general binary lifecycle support.
