# Arise 0.0.53

Fix a core installation bug that could put 32-bit glibc startup objects and
libraries outside the profile's required directories. On the reported host,
`LIBDIR_x86=lib` required `/usr/lib`, but Arise installed the objects under
`/usr/lib32`. A later libxcrypt build could not find `Scrt1.o` or `crti.o` even
though GCC was correctly invoked with `-m32`.

- Honor `LIBDIR_${ABI}` in `get_libdir`, with Portage's `lib` fallback. This
  corrects explicit ebuild paths, `econf` defaults and library helpers for both
  x86 layouts, x32, nested directories and other profile-defined ABIs.
- Preserve `SYMLINK_LIB`, `KERNEL_ABI` and `FAKE_TARGETS_*` in the build
  environment, including glibc's regeneration of multilib settings.
- Advance the execution ABI to **7**. Older marked Arise artifacts are
  scheduled for repair even when their version and USE flags are unchanged.
  This is conservative and can rebuild packages that did not use the affected
  helper. Unmarked Portage packages retain their normal policy.
- Preserve execution provenance in XPAK/GPKG captures and binary indexes.
  Reject incompatible Arise binaries during selection and before installation,
  including older XPAKs whose marker survives only in captured VDB evidence.
- Apply EAPI 8 install rules to EAPI 9 too, and match Portage's destination
  creation and existing-directory mode preservation.
- Require complete Portage helper-image comparisons across EAPI 7/8/9 and
  profile layouts, actual multilib eclass setup, and real ELF32 consumer links
  in the release contract checks.

## Recovery and upgrade

Upgrading Arise does not itself move already misplaced glibc files. If startup
objects are affected, restore the installed glibc with Portage first. For the
reported version:

```sh
emerge --oneshot =sys-libs/glibc-2.43-r4
x86_64-pc-linux-gnu-gcc -m32 -print-file-name=Scrt1.o
x86_64-pc-linux-gnu-gcc -m32 -print-file-name=crti.o
```

Both queries should return existing paths rather than bare filenames. Then
verify a real multilib build. Restore package ownership through Portage rather
than moving library directories or adding directory symlinks by hand.

Install the corrected Arise version with Portage:

```sh
emaint sync -r arise-overlay
emerge --oneshot =sys-apps/arise-0.0.53
arise index
```

Rerun the original update command afterward to resolve repair work against the
current installed state.

## Verification

Before/after regressions reproduce the layout, environment transport and
artifact-reuse failures. The expanded Portage comparisons retain complete
path, content and permission checks. An actual libxcrypt 4.5.2-r1 build covers
both x86 and amd64, checks compatibility and current libraries' ELF classes,
and merges only into a disposable root. Full tests, vet, race checks, offline
artifact reproducibility, packaging and Arise self-build/install gates are
required before publication.

The reported host's Portage glibc reinstall restored startup-file lookup.
A full glibc rebuild/merge acceptance run and live-host world-update acceptance
remain separate from the disposable tests. See the
[profile library layout audit](../audits/PROFILE_LIBRARY_LAYOUT_2026-11-09.md)
for evidence, recovery details and limits. Arise remains experimental and
`~amd64`.
