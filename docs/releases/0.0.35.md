# Arise 0.0.35

Bare package names now follow emerge's category preference. When exactly one
ordinary package shares its name with `acct-user`, `acct-group`, or `virtual`
packages, Arise selects the ordinary package and resolves its dependencies.

For example, `arise -pav imvault witmoot` selects `www-apps/imvault` and
`www-apps/witmoot`, including their required service users and groups. The
qualified-name workaround described in 0.0.34 is no longer needed for this case.

Names shared by multiple ordinary packages, or only by multiple account/virtual
packages, remain ambiguous and require a category. Explicit account or virtual
targets retain their meaning.

The resolver and independent plan audit apply the same category preference.
Regression tests cover account and virtual collisions, genuine ambiguity,
explicit account targets, account dependency validation, and bare-name
resolution after indexing an uncached overlay.
