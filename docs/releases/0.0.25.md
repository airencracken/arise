# Arise 0.0.25

Arise 0.0.25 improves live package concurrency and missing-package
diagnostics based on findings from bringing a fresh Gentoo stage3 to a
bootable BIOS VPS with Arise.

Live source builds and binary extraction no longer hold Portage's VDB lock.
Arise prepares the package image first, then acquires the shared
Portage-compatible lock immediately before `pkg_preinst` and filesystem/VDB
mutation. Independent Arise processes can therefore build concurrently while
commits remain serialized.

Every prepared package is revalidated after acquiring the lock. Successful
Arise-owned commits advance the expected state fingerprint before releasing
the lock, allowing dependency-ordered multi-package transactions to continue
while rejecting an unrelated package-state or policy change before the next
mutation. Recovery-set publication remains inside the first locked mutation
boundary and runs exactly once.

Missing-package suggestions now compare package names independently from
categories. Exact names and close spelling corrections in another Gentoo
category outrank weaker same-category matches. For example, both
`sys-apps/logrotate` and `sys-apps/logrote` suggest
`app-admin/logrotate`.

## Upgrade

The source package remains available through the Arise overlay:

```sh
arise sync
arise -1 --reinstall =sys-apps/arise-0.0.25
arise --version
```

The release also provides a reproducible static `linux-amd64` bundle for
installing or recovering Arise without first compiling it on the target.

The final command prints `arise 0.0.25`.
