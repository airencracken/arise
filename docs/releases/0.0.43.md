# Arise 0.0.43

Profile inspection and comparison for the existing experimental `~amd64` overlay.

- Add `arise profile show` to inspect inherited layers, merged `make.defaults`,
  USE masks and forces, package USE policy, masks and unmasks, and system and
  provided packages. `--explain` includes ordered source contributions.
- Align human-readable output in columns, wrap it to the terminal width, and
  apply the existing color controls. Redirected output stays readable and JSON
  remains uncolored.
- Add `arise profile list` to discover advertised profiles for the active
  architecture, or all architectures with `--all`, including selection,
  status and deprecation metadata.
- Add `arise profile diff TARGET` to compare the active profile with another
  profile, or provide two explicit selectors. Compare effective defaults and
  policy while retaining order where it affects evaluation. Neither command
  changes the active profile or local configuration.
- Publish versioned JSON schemas for inspection, discovery and comparison,
  and document the commands in help, completion and both manuals.
- Move profile evaluation, discovery, comparison and provenance into Gentooling.
  Arise pins commit `7bd5ddc91c118cfc8197d34458a321df8cdaebc7` through the Go
  module version `v0.11.2-0.20261022220744-7bd5ddc91c11`, without a local override.
  The library exposes each assignment's expression, expansion, source line and
  effective before/after values, plus package USE and visibility evaluation.

Inspection reports profile contributions only. Local configuration, environment
and package IUSE are outside the report's effective-default scope. Unsupported
profile files are listed explicitly. Arise's `--explain` displays contributions;
the richer variable trace is currently a library API. Targeted `why` queries,
rebuild planning and profile migration remain open. An advertised profile with
the same architecture is a discovery candidate, not a compatibility guarantee.

The full fresh-stage3 update, interruption/resume, linkage and reboot acceptance
run remains deferred. Profile fixtures and read-only host inspection do not
establish that acceptance gate. The final live-system installation remains a
separate manual canary.
