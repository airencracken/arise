# Arise 0.0.6

Arise 0.0.6 makes the built-in go-git implementation the primary repository
transport. It also improves synchronization output, corrects world-update
candidate discovery and conflict reporting, and establishes architecture
decision records and an independent plan-validation roadmap.

## Repository synchronization

Clone, fetch, reset, origin discovery, and repository-tree comparison now use
go-git first. System Git remains a compatibility fallback after a genuine
built-in transport failure. It is not used to bypass dirty-worktree,
detached-HEAD, existing-target, or other policy failures. Rsync remains
available only for repositories explicitly configured with `sync-type=rsync`.

Clone operations stage into a sibling temporary directory, validate the
result, and publish it with a rename. Failed and cancelled clones clean up
their staging directory without replacing an existing target. Update failures
preserve the existing worktree.

## Measured rationale

On the retained local Git-protocol benchmark fixture, median built-in
operations were:

- approximately 15 ms for clone, compared with 121 ms through system Git;
- approximately 15 ms for a no-op update, compared with 134 ms;
- approximately 24 ms for an incremental update, compared with 141 ms.

The in-process path allocates more memory in the Arise process. The system Git
allocation figures do not include the child process, so they are not a
whole-operation memory comparison. Arise prioritizes the measured latency
advantage for repository synchronization while retaining the fallback for
compatibility.

## Validation

Transport contract tests cover primary-driver ordering, successful fallback,
policy-error isolation, atomic publication, cancellation cleanup, corrupt
repositories, and preservation of existing targets. Differential tests compare
the built-in change summary with system Git across repository histories.
Benchmarks for clone, no-op update, and incremental update remain in the test
suite.

The decisions and their revisit conditions are recorded in:

- [ADR-0001: Prioritize measured speed over memory usage](../adr/0001-prioritize-measured-speed.md)
- [ADR-0002: Use go-git as the primary repository transport](../adr/0002-use-go-git-as-primary-transport.md)

## Synchronization output

Repository synchronization now applies semantic color roles to package
changes while preserving static and no-color output behavior. Git and rsync
updates report concise eix-style package transitions with the previous and new
best non-live versions plus the package description:

```text
[>]   == app-containers/lxc-templates (3.0.4_p20240917 -> 3.0.4_p20260719): Old style template scripts for LXC
```

Unchanged live ebuilds such as `9999` no longer obscure stable-version
transitions.

## World-update resolution and diagnostics

Repository candidates without an md5-cache are discovered through Portage's
authoritative evaluated metadata cache. This prevents valid overlay upgrades
from disappearing from world-update plans.

When an installed package constrains a visible update, Arise now reports the
skipped update with the exact requiring package and atom. Internal circular
graph traversal paths are no longer emitted as user warnings or JSON warning
records.

Regression tests cover evaluated metadata fallback, constrained updates,
warning rendering, structured output, and bounded cycle handling.

## Independent plan validation roadmap

The new
[independent plan-validation plan](../planning/INDEPENDENT_PLAN_VALIDATION_PLAN.md)
defines a final-state validator, bounded decision ledger, mutation and
adversarial gates, immutable fixtures, and classified Arise-versus-Portage
differentials. Portage remains valuable comparative evidence without becoming
an action-for-action correctness oracle.
