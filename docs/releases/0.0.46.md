# Arise 0.0.46

Fix upgrades blocked by recovery capture after protected configuration updates
have been accepted or removed by dispatch-conf or another config-update tool.

- Resolve recorded `._cfgNNNN_name` paths to the current configuration when
  capturing an installed package. A consumed staged update no longer blocks
  capture when the current configuration exists.
- Save the current configuration together with any still-pending update in
  recovery and GPKG archives. Preserve the original VDB as recovery evidence,
  and rebuild ownership from the actual restored payload during recovery.
- Keep missing ordinary files, malformed update names, duplicate records, and
  symlink escapes as capture errors.
- Preserve complete execution error lines so long recovery failures show the
  failing pathname and cause instead of being cut off at 160 bytes.

Regression coverage includes consumed and pending updates, archive round trips,
and dispatch-conf acceptance followed by an upgrade and recovery-set restore.

Arise remains experimental and `~amd64`. The full fresh-stage3 update,
interruption/resume, linkage and reboot acceptance run remains deferred.
The final live-system installation remains a separate manual canary.

See the [compatibility matrix](../compatibility/PORTAGE_COMPATIBILITY_MATRIX.md)
and [remaining work](../../PUNCHLIST.md).
