# Arise 0.0.15

Arise 0.0.15 fixes release-blocking `REQUIRED_USE` validation failures in deep
newuse world updates.

## Installed REQUIRED_USE validation

Independent validation now evaluates unchanged installed packages against the
`REQUIRED_USE` recorded in VDB. It no longer combines installed USE state with
constraints from a newer repository ebuild of the same version.

This fixes false failures such as `net-misc/curl-8.21.0` being rejected during
a world update even though the resolver had not selected an invalid curl USE
state. Planned installs and rebuilds continue to be checked against the
selected repository ebuild's `REQUIRED_USE`.

Both resolver and independent validation now evaluate negated REQUIRED_USE
leaves such as `!mbedtls` as disabled-flag requirements. Previously they were
misread as literal flag names, causing valid cardinality expressions to fail.

Arise consumes Gentooling 0.9.1, which exposes installed `REQUIRED_USE` through
its mutation-checked VDB inventory API.

## Update command spelling

The ambiguous `update` subcommand has been removed. Package updates use the
Portage-compatible `-u` or `--update` option, with dependency traversal and USE
rebuild policy remaining explicit:

```sh
arise -uDN @world
```

## Upgrade

```sh
arise sync
arise -1 --reinstall =sys-apps/arise-0.0.15
arise --version
```

The final command prints `arise 0.0.15`.
