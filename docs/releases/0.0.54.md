# Arise 0.0.54

Fix rollback backups blocking updates when installed package records refer to
files that package hooks have deliberately removed. Execution errors now
explain what failed, which package or path is affected, and what to do next.

- Record already absent payload paths in recovery backups instead of treating
  them as read failures. Gentoo's kernel configuration normally removes
  `initrd` and `uki.efi` placeholders, so those records must not block the next
  update. Protected-config dispatch and other removed payloads use the same
  capture contract. Capture preserves the live package database.
- Keep actual read failures, incompatible existing file types, unsafe path
  parents and observed capture races fatal. Missing paths are rechecked before
  publishing the archive. Standard GPKG capture also omits absent files.
- Explain rollback capture, build failures, compiler probes, storage and access
  errors, package locks, changed plans and compatibility problems in ordinary
  language. Preserve the affected paths and durable logs; show technical
  wrapper chains with `--verbose`.
- Distinguish committed package changes with failed follow-up work from failed
  installation work. Failed automatic rollback directs you to recovery status.
  Simultaneous package failures retain each package's cause and log.

## Upgrade

Install this version with Portage before retrying the blocked update:

```sh
emaint sync -r arise-overlay
emerge --oneshot =sys-apps/arise-0.0.54
arise index
```

Then rerun the original update command. You do not need to recreate the kernel
placeholders or edit installed package records.

New recovery artifacts use schema 2 to record absence explicitly. This release
can read schema 1 and 2; older releases cannot read newly created schema 2
backups. Use this version or a compatible newer version to restore those
backups. The recovery-set schema and execution ABI remain unchanged.

## Verification

Before/after regressions reproduce missing-payload capture failures in both
recovery and GPKG formats and a real source-build failure that bypassed the
structured error renderer. Integration coverage backs up, upgrades and restores
a gzip/kernel package set without recreating removed placeholders. Tests cover
schema compatibility, unsafe paths, changed capture state, committed follow-up
work, failed rollback and simultaneous failures.

Full tests, vet, race checks, static and offline reproducible builds, Portage
packaging checks, the live phase-contract lane and Arise's own disposable-root
build/install gate are required before publication. Documentation and complexity
checks also pass. See the
[recovery and diagnostics audit](../audits/RECOVERY_CAPTURE_AND_DIAGNOSTICS_2026-11-09.md).
The reported host's full world update remains a separate acceptance run.
