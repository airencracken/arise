# Arise 0.0.28

Arise 0.0.28 fixes fresh-stage3 bootstrap compatibility and two package-plan
and build failures observed on live Gentoo systems.

Repository discovery now applies Portage's shipped configuration from
`/usr/share/portage/config/repos.conf` before local entries from
`/etc/portage/repos.conf`. A fresh stage3 can therefore discover the Gentoo
repository and load its active profile before an administrator creates a local
Gentoo repository section. Local sections override shipped defaults while
retaining settings they do not replace. Install, sync, index, search, info, and
maintenance commands all use the same effective repository view.

The phase worker now implements Portage's `addread`, `addwrite`, `adddeny`, and
`addpredict` sandbox path helpers. Ebuilds such as OpenSSH can extend sandbox
policy during configuration instead of failing with `addwrite: command not
found`.

Any-of dependency resolution now prefers a singleton alternative already
scheduled elsewhere in the plan. A deep world update that has selected
`gentoo-kernel-bin` no longer adds `gentoo-kernel` merely because
`virtual/dist-kernel` lists the source implementation first. Package counts,
download totals, and the selected implementation remain consistent with the
requested binary-kernel upgrade.

The release includes fresh-stage3 repository-layering tests, phase-worker
integration coverage, a binary-kernel resolver regression, adversarial and
mutation-tagged tests, and the full repository test suite.

## Upgrade

The source package remains available through the Arise overlay:

```sh
arise sync
arise -1 --reinstall =sys-apps/arise-0.0.28
arise --version
```

Keep Portage installed as the reference and recovery implementation. The final
command prints `arise 0.0.28`.
