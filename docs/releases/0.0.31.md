# Arise 0.0.31

Arise 0.0.31 fixes package-removal data loss, kernel update selection, download
estimates, and command confirmation. It also tightens the complexity ratchets.

## Correctness

- Uninstall and replacement cleanup preserve modified files, changed timestamps,
  changed object types, and retargeted symlinks. Unchanged obsolete files are
  still removed, and failures retain journal rollback behavior.
- The certified removal-hook check rejects OR conditions, alternate ROOT
  expressions, shell escapes, and hook redefinitions that could execute on a
  live root.
- Version-pinned virtual updates retain an installed kernel provider across
  version and slot changes, regardless of explicit target order.
- Architecture flags remain in effective USE, so architecture-specific binary
  kernel downloads and dependencies are selected correctly.
- Download totals verify cached files and count shared Manifest artifacts once.
  Truncated or corrupt cache entries no longer produce a zero-byte estimate.
- Rejected replacement actions leave the independent validator's simulated
  package state unchanged.
- Pretend/preflight commands preserve resume state, including `--skipfirst`.

## Usability

`arise uninstall codex` works when the installed name is unambiguous.
Category/package atoms, versions, slots, and repository restrictions are also
supported. All matching installed versions are selected; overlapping requests
are deduplicated. Ambiguous names list the category/package choices.

`remove` and `unmerge` are aliases, with help and Bash completion support.
Both install and uninstall now honor `--ask` for normal executable plans.
Only an explicit `y` or `yes` accepts the prompt.

## Complexity and validation

The production complexity limits move from an average of 7.89, 20 functions
above 50, and a maximum of 221 to 7.87, 19, and 215 respectively. Uninstall's
main function falls from 59 to 48 through separation of target preparation,
confirmation, and pre-existing-conflict handling. File-removal checks and
source-URI parsing are shared between their callers.

Regression coverage includes filesystem transactions and rollback, adversarial
shell input, resolver/provider order, architecture download contracts, CLI
routes, pretend JSON output, and declined interactive removal. Targeted source
mutations verify that the new tests detect removal of the fixes.

The release process verifies static builds, the full test suite, vet, race
tests, benchmarks, and reproducible offline vendor artifacts. The final
live-system installation remains a separate manual canary.
