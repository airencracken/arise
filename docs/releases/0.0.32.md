# Arise 0.0.32

Arise 0.0.32 corrects dependency-lifetime validation that could refuse an
unrelated installation after a compiler upgrade. An already installed age
package's historical Go build dependency no longer blocks installing Arise.

- Retained packages keep runtime and post-install dependency checks without
  requiring their historical build or installation tools.
- Binary installs do not require source build dependencies; installation tools
  and runtime dependencies remain validated.
- Reinstalling a package cannot waive its existing dependency failures.
- Post-install prediction preserves retained and prebuilt package metadata.
- DEPEND checks use the appropriate dependency root for the package's EAPI.
- Validation errors identify the dependency class, such as BDEPEND or RDEPEND.

Regression coverage includes the age/Go failure through the CLI audit route,
all dependency classes, source/binary evidence, reinstalls, EAPI dependency
roots, metadata preservation, and forged merge types. Five targeted source
mutations are detected. Existing complexity limits remain unchanged.
