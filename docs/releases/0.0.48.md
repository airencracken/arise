# Arise 0.0.48

Fix `pkg_preinst` failures caused by Bash completion QA helpers leaking into
saved package environments, including the reported caddy-analyzer 0.8.1
`/..?(/*))` syntax error.

- Run each install QA script in its own subshell, matching Portage's boundary.
  Keep image edits and diagnostics while discarding QA variables, functions,
  shell options, traps, and directory changes.
- Confine the QA driver's environment defaults to its own shell as well.
- Load extended-pattern function definitions from existing saved environments
  with the required parser option, then restore the worker's option before
  running the package hook.
- Report failed QA scripts and continue with subsequent checks according to
  Portage's advisory QA execution policy.

The live regression reproduces the exact syntax error with Portage's installed
completion QA check before the fix and completes `pkg_preinst` afterward.
Portable tests cover state isolation between QA scripts and package phases,
retained image edits, and failures using ordinary return, `exit`, and `die`.

See the [QA isolation follow-up](../audits/INSTALL_QA_ISOLATION_2026-11-05.md)
for the boundary missed by the 0.0.47 audit. The execution ABI remains 5.

Arise remains experimental and `~amd64`. The full fresh-stage3 update,
interruption/resume, linkage and reboot acceptance run remains deferred.
The final live-system installation remains a separate manual canary.
