# Arise 0.0.44

Blocker-removal fixes, package history and time estimates for the existing
experimental `~amd64` overlay.

- Execute planned blocker removals after the requesting package has built,
  under the same mutation lock as its merge. Validate installed package
  identity and lifecycle files before removal, retain transaction journals,
  and preserve pending work for resume. Reject unsupported removal plans
  before execution.
- Clarify skipped world updates and include planned removals in approval,
  progress and JSON plan output.
- Add `arise history`, `arise history stats` and `arise history incomplete`
  to query Portage-compatible merge logs, including compressed and rotated
  logs, date and package filters, and versioned JSON output. Emit standard
  Portage unmerge records for new removals.
- Improve opt-in `--show-estimates` with successful historical timings,
  repository and root matching, dependency-aware elapsed-time forecasts,
  coverage reporting and execution-time updates. Unknown or exceeded timings
  remain explicitly unknown; estimates do not affect scheduling or approval.
- Add regression coverage for blocker-removal execution and failure paths,
  history parsing and CLI behavior, and timing statistics and forecasts.

The full fresh-stage3 update, interruption/resume, linkage and reboot acceptance
run remains deferred. The final live-system installation remains a separate
manual canary.

See the [history and timing guide](../history.md),
[compatibility matrix](../compatibility/PORTAGE_COMPATIBILITY_MATRIX.md) and
[remaining work](../../PUNCHLIST.md).
