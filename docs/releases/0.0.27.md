# Arise 0.0.27

Arise 0.0.27 fixes a critical live-service replacement bug. EAPI 7 and newer
now receive the Package Manager Specification representation of the native
system root: empty `ROOT` and `EROOT` values. Arise previously exported `/`,
which made ebuild lifecycle hooks mistake a live installation for an alternate
root and skip service handoff logic.

Replacement lifecycle phases now receive `REPLACING_VERSIONS` and
`REPLACED_BY_VERSION` for both upgrades and same-version reinstalls. This lets
daemon packages execute the same guarded reload or restart behavior they use
under Portage. In particular, the Gentoo OpenSSH ebuild can validate and
restart an active OpenRC or systemd service after a relevant version change,
instead of leaving an old listener paired with newly installed helper binaries.

Arise also compares live process executable identities across a completed
transaction and emits a critical diagnostic when a process remains mapped to
an executable replaced during that transaction. This is defense in depth for
all daemons rather than package-specific handling.

Signal-driven cancellation now removes the uniquely named package workspace.
Long builds terminated with SIGTERM no longer strand multi-gigabyte temporary
trees merely because `fail-clean` is disabled; genuine build failures retain
the configured Portage-compatible behavior.

The release includes unit, adversarial, lifecycle integration, post-commit
failure, cancellation, and race coverage. The full repository suite and the
native-root service-handoff tests were run on Gentoo with Portage sandboxing.

## Upgrade

The source package remains available through the Arise overlay:

```sh
arise sync
arise -1 --reinstall =sys-apps/arise-0.0.27
arise --version
```

Keep independent recovery access available while upgrading package-management
or remote-access infrastructure. The final command prints `arise 0.0.27`.
