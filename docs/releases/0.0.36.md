# Arise 0.0.36

New installations now honor `CONFIG_PROTECT` when a regular configuration file
already exists. This fixes migration from a manual Imvault installation failing
with `live new-install canary refuses existing target /etc/conf.d/imvault`.

Local settings and logrotate rules remain in place. If the packaged defaults
differ, Arise stages them as `._cfgNNNN_` updates for `dispatch-conf` or
`etc-update`. Identical defaults do not create unnecessary update files.
Binary-package installation now passes the same `CONFIG_PROTECT` and
`CONFIG_PROTECT_MASK` settings to the merge engine as source installation.

Regression tests cover protected paths, masks, file-type changes, pending config
updates, preserved application data, and rollback after a payload-sync failure.
Unprotected existing files and differing symlinks still trigger the live
installation guard. In particular, a manually installed `/usr/bin/imvault` is
outside the default `/etc` protection policy; the default `make install` path
of `/usr/local/bin/imvault` does not conflict with the package's executable.
