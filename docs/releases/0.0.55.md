# Arise 0.0.55

Arise could install a package after a required patch failed. In
`app-misc/ca-certificates-20260816.3.131.1-r1`, it treated the `-p2` argument
to `eapply` as a filename. The unpatched updater created 118 certificate links
pointing into the build tree. They resolved during installation and broke when
Arise removed that tree.

## Fixes

- Forward ebuild-supplied patch options for individual files and directories.
  Failed patches stop the build. User patches use the same implementation and
  the worker records completion only after the whole patch set succeeds.
- Propagate required helper failures during unpack, build, and install. The
  audit reproduced missing inputs in file, executable, documentation,
  symlink, and permission helpers. A later successful shell command could
  hide the error. Explicitly nonfatal install and make calls can still
  inspect the exit status. A fatal error in a phase subshell also prevents
  the phase from committing a successful environment snapshot. Calling a helper
  banned by the selected EAPI stops the phase even if the ebuild continues.
- Inspect source-built package images before binary publication and before
  merge. A symlink into the package's temporary source tree now fails with
  both the installed path and its target. An ordinary system symlink may
  point to a target that another package will install later.

## Upgrade and repair

Install the new package manager using Portage. On a machine affected by the
certificate issue, rebuild the certificates from source to replace the updater,
links, and installed file records.

```sh
emaint sync -r arise-overlay
emerge --oneshot =sys-apps/arise-0.0.55
emerge --oneshot --usepkg=n app-misc/ca-certificates
arise index
```

The Arise execution ABI advances from 7 to 8. Older Arise packages do not
record which helper calls succeeded. Arise uses its existing ABI repair
policy for installed packages and rejects older marked binary packages.
A world update can therefore propose additional source rebuilds.

The regression was reproduced with the affected Gentoo ebuild. With the fixed
worker all 118 staged PEM links resolved after removal of the source tree.
