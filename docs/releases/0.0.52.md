# Arise 0.0.52

Fix install finalization for packages containing thin archives, including the
reported `sys-kernel/gentoo-kernel-bin-6.18.60` failure, and supply the verbose
logging helper used by Portage's executable QA checks.

- Classify installed objects before stripping. Leave thin archives and their
  external members unchanged, matching Portage's handling.
- Strip only debug information from regular archives and rebuild their index,
  preserving local symbols that the previous flags removed.
- Provide quiet-aware `__vecho` and `__quiet_mode` helpers inside the isolated
  QA environment, keeping them out of saved package state and lifecycle hooks.
- Require real Portage comparisons for archive finalization and the installed
  executable-QA warning path in addition to the EAPI 7/8/9 and Bash completion
  QA release checks.

Regression tests reproduced the thin-archive failure, regular-archive symbol
loss and missing QA helper before the fix. Coverage includes compiled ELF
objects and archives, excluded files, external archive members, archive linking
and execution, quiet mode and lifecycle-state isolation. The execution ABI
remains **6**.

After upgrading, rerun the original package-update command to resolve against
current installed state. Scanelf diagnostics and process-restart notices may
still appear. A complete kernel-bin merge and live-host world update remain
separate acceptance checks; this release does not add split-debug or
cross-toolchain support.

See the [install finalization audit](../audits/INSTALL_FINALIZATION_2026-11-07.md)
for the cause, Portage comparisons and validation limits. Arise remains
experimental and `~amd64`.
