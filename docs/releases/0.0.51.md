# Arise 0.0.51

Allow unrelated package installs during a long world update without treating
every change to the installed database as invalidating the prepared package.
This addresses the reported ffmpeg merge failure after concurrent comfyware
installs.

- Wait for the operation lock and independently revalidate the remaining frozen
  actions against fresh installed dependency, USE and ABI bindings.
- Accept compatible unrelated installs, removals and world bookkeeping. Check
  new reverse consumers and blockers, and retain strict policy/source and
  prepared-image dependency checks.
- Exclude completed actions, prerequisites and selected decisions from replay
  while preserving the original approved plan evidence.
- Give concurrent Arise commands separate resume checkpoints when the default
  is already owned. Print the separate recovery path and retain it on failure.
- Hold checkpoint ownership through final world bookkeeping. Reject active or
  stale resume requests before they can overwrite or retire another command's
  progress; release ownership automatically when a process exits.

Before/after regressions reproduce both the unrelated-install rejection and
checkpoint overwrite against the previous behavior. Process integration tests
exercise real operation locks with temporary package databases in serial and
parallel executor settings. The execution ABI remains **6**.

Older running Arise processes do not participate in the new checkpoint protocol.
Finish other package operations before upgrading, then rerun the original
world-update command to resolve against current installed state. An older
shared resume file may have been replaced by a concurrent Arise command.
Actual dependency or policy changes requiring a different plan still stop with
resume guidance; Arise does not silently approve additional actions or reuse
images whose dependency inputs changed.

See the [concurrency audit](../audits/CONCURRENT_PACKAGE_STATE_2026-11-06.md)
for the checks, regression evidence and limits. Arise remains experimental and
`~amd64`; a full live-host world update and fresh-stage3 acceptance remain
separate checks.
