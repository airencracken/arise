# Arise 0.0.49

Fix Arise's self-upgrade failure and the broader shell-state contract problems
behind it. The published source ebuild's `ARISE_COMMIT` was incorrectly removed
between phases, producing an empty vendor-manifest `-commit` argument.

- Separate worker controls and helper functions into the PMS-reserved namespace,
  preserving package variables and functions regardless of application prefix.
- Preserve function export and trace attributes, strip readonly attributes as
  Portage does, and keep eclass assignments outside worker-local name collisions.
- Keep ambient session, proxy and cache settings out of package state; restore
  current locale and feature configuration when loading installed environments.
- Migrate old helper state and save structured lifecycle metadata, so quoted
  package text cannot invent hooks or select the wrong snapshot format.
- Close the event descriptor during package phases so background children
  cannot hold a completed worker open.
- Require EAPI 7/8/9 comparisons against Portage and an Arise-driven self-build
  through test, install and lifecycle hooks before release publication.

The execution ABI advances to **6**. Packages built with older Arise ABIs are
selected for rebuilding because lost inputs could affect installed payloads.
Unmarked Portage-built packages retain their existing selection behavior.

Use Portage to bootstrap this version if the installed Arise cannot build its
replacement:

```sh
emaint sync -r arise-overlay
emerge -1 =sys-apps/arise-0.0.49
```

The [shell-state contract audit](../audits/SHELL_STATE_CONTRACT_2026-11-05.md)
records before/after regressions, the reference comparisons, migration behavior,
and remaining limits. Arise remains experimental and `~amd64`; the full host
update and fresh-stage3 acceptance run remain separate checks.
