# Arise 0.0.5

Arise 0.0.5 substantially reduces the cost of resolving large dependency
graphs and introduces the first filesystem rollback contracts.

## Performance

On the correctness-gated warm `@world` workload, the complete C2 tuning cycle
reduced:

- median wall time from 3.45 seconds to 2.48 seconds, a 28.1% improvement;
- median CPU time from 7.72 seconds to 4.63 seconds, a 40.0% improvement;
- median peak RSS from 812,612 KiB to 568,604 KiB, a 30.0% improvement;
- profiled allocation from 2,645.55 MiB to 733.20 MiB, a 72.3% reduction.

The improvements come from reusing the state-fingerprint buffer, caching
implicit USE expansion prefixes, loading a resolver-specific VDB projection,
streaming dependency metadata into the graph, and handing already parsed
dependency atoms directly to the resolver.

Every candidate was checked against the same live plan and whole-state
digests. Experiments that regressed runtime or memory, including broad
policy-result caching and reverse-edge preallocation, were removed.

## Rollback groundwork

This release adds filesystem rollback coverage and durable record contracts,
including validation for mount coverage, provider capabilities, record
identity, and adversarial input. These contracts are prototypes and do not
enable unsupported live mutation by themselves.

## Measurement and validation

The performance harness now records process-tree memory, process counts, and
storage I/O. New regression fixtures cover dependency streaming, resolver-only
VDB state, parsed-edge conversion, rollback records, and authorization
boundaries.

The release was gated by the full test suite, vet, adversarial and mutation
tests, race tests, static linking, module verification, and exact live
resolver output.
