# Correctness, complexity, and usability audit, 2026-09-08

Baseline: master `5570550` (Arise 0.0.30). The audit covered resolver/provider
selection, effective USE, uninstall routing and matching, lifecycle guards,
merge/unmerge cleanup, Manifest sizing and fetch verification, independent
plan application, confirmation, resume state, and release automation.

## Confirmed findings and fixes

| Finding | Resolution |
|---|---|
| Unmerge deleted modified configuration files | Shared removal code checks type, recorded timestamp, and file digest or symlink target before deletion. Modified payloads are retained, including outside `/etc`, matching Portage's normal removal behavior. |
| Replacement cleanup had the same deletion bug | Uses the same removal helper; tests cover both operations and rollback. |
| Live-root hook guard admitted always-true OR conditions | A strict structural subset admits only ROOT-empty guards and simple unreachable bodies. Alternate declarations, escaping shell syntax, and redefinitions are rejected. |
| Download totals ignored corrupt cache entries and duplicated shared archives | Totals use the fetcher's Manifest plan and verification primitives, deduplicate artifact identities, reject conflicts/overflow, and do not consume artifacts on failed calls. |
| Version-pinned virtuals selected an extra kernel provider | Prefer the installed provider when neither required new version is installed, using the correct dependency domain and retaining fallback behavior. |
| Architecture-dependent downloads were missing | Preserve the architecture flag in effective candidate USE without adding it to declared IUSE. |
| Uninstall required exact CPVs | Resolve installed names and constraints, report ambiguity, deduplicate matches, and route remove/unmerge aliases. |
| Install and uninstall ignored ordinary --ask | A shared confirmation primitive requires an explicit affirmative answer before execution. Declined removal is tested through the real command path. |
| Pretend/preflight could delete or update resume state | Cleanup is execution-only; read-only skipfirst changes the in-memory target list. |
| A rejected validator replacement removed its preimage | Validate all action conditions before updating the simulated state. |

No confirmed finding from this audit remains intentionally open. This is a
bounded source audit with automated evidence, not a claim that the project is
free of undiscovered bugs.

## Complexity

Measured with gocyclo 0.6.0, excluding tests under cmd, internal, and misc:

| Metric | Released baseline | New limit |
|---|---:|---:|
| Average | 7.89 | 7.87 |
| Functions above 50 | 20 | 19 |
| Maximum | 221 | 215 |
| runUninstall | 59 | 48 |

The changed removal and confirmation paths now use smaller shared functions;
Manifest sizing no longer maintains a second source-URI parser. Hot resolver
functions were not broadly restructured. The release benchmark lane verifies
representative wall-clock benchmarks and allocations; future hotspot work
still requires production-style resolver timings as described in the prior
complexity audit.

## Validation

Permanent regressions cover unit behavior, resolver-to-Manifest integration,
filesystem transaction atomicity/rollback, JSON schema/API shape, command
routes and completion, adversarial inputs, and duplicate/order invariants.
Focused source mutations remove digest checking, hook-redefinition checking,
cache verification, replacement atomicity, confirmation, and read-only resume
protection; the corresponding tests must fail.

The release gates additionally run static compilation, the full Go suite,
vet, race tests, benchmark smoke tests, and reproducible offline source/vendor
builds. Tests use temporary roots; they do not uninstall host packages.
